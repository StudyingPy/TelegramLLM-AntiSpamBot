# 视觉按素材触发与 Jev v3

纯文字和普通 Unicode emoji 不再因为发言者处于观察期、是会员或正文短，就默认查头像并调用视觉模型。自定义 emoji（含 caption entities）、图片、贴纸/会员动画、动画和视频仍通过原来的排版取帧流程审核。

头像/状态补查仅在有具体线索时启用：短消息明确指向自己的头像、简介或主页；未受老用户保护的短招揽（如“会网购的来”）；或短而含糊的消息配合该账号已有资料中的明确导流/广告文字。泛用 Bio 链接、会员标志和账号新旧本身不触发。引用/代码和已验证抽奖口令不触发仅资料检查；正文确有自定义 emoji 或媒体时仍查正文素材。资料检查理由写入视觉侧库的 routing 字段。未触发视觉的消息继续使用 Jev→MiMo 文字复核，不会跳过审核。

这是基于现有线索选择视觉材料，不能承诺发现没有任何文字线索的头像/状态广告。它有意减少对正常聊天的图像请求；原有资料单独命中最多投票的边界保留。

Jev Questions 更新为 `telegram-message-evidence-zh-v3`：明确无链接招揽、代收高薪、混淆金额、重复行为与当前账号资料的印证关系，补充已验证抽奖口令、正常讨论和引用举报边界。Jev只读文字和素材清单，不能把自定义emoji占位符当成已经看见的图像，也不能把单个@提及归为群体骚扰。保留 Noul/Choice 类型、类别键和 Jev 初审→MiMo 独立复核，处罚门槛不变。

旧 v2 Questions 冻结为 `SHORT_ZH_QUESTIONS`，`short_zh_full` 实验控制组保持原哈希；实验工具增加 `evidence_zh_full`，不篡改旧实验结果。v3 Questions 哈希为 `ac682b0592b43d4c76e63fa836fd6d02f7f0079f564764275efce0543b843558`。

14条合成消息的新旧对照仅验证指定边界，不能用于声称线上总体误判率或召回率。原文/结果与部署辅助文件保留在忽略目录，不提交实际群聊天数据。
