# 重复招揽与抽奖口令保护

针对“会网购的来”这种每隔十几分钟发送、把邀请链接藏在 Bio 的广告，使用独立于短时链接重复规则的行为证据。

| 条件 | 结果 |
| --- | --- |
| 仅普通复读、签到、接龙、抽奖口令 | 不进入本规则的招揽计数 |
| 同群 6 小时内相同短招揽文案，同账号累计 3 条 | 检查当前账号的资料引流证据 |
| 同群 6 小时内相同短招揽文案，累计 3 个不同账号 | 同样检查当前账号，之前账号不连带处罚 |
| 达到任一阈值，当前账号 Bio 有 Telegram 邀请链接，或昵称/Bio 明确引导看简介、主页、私聊联系 | 本地封禁，并将该账号自己的同文消息 ID 交给现有清理流程 |
| 同账号达到阈值，但没有资料引流证据 | 模型审核，保留投票兜底；后续同文仍适用现有“重复未结束投票”规则 |
| 仅跨账号达到阈值，当前账号没有独立引流证据 | 携带重复统计交给模型，无本地强制封禁或投票 |
| 获得老用户保护，命中上述本地处罚 | 仍先经模型，模型判正常可放行 |

`RECRUITMENT_REPEAT_WINDOW_SECONDS` 默认 21600；同账号门槛由 `RECRUITMENT_REPEAT_MIN_MESSAGES` 控制，跨账号沿用 `REPEAT_MIN_DISTINCT_SENDERS`。两种门槛均至少为 3。本规则匹配完整短招揽句式，如“会网购的来”“想赚钱的来”“愿意兼职的朋友来私聊我”；不会把包含这些词的讨论、引用举报或任意相似骨架直接视作同文。正文上限 120 字符；计数键保留数字及文字，仅消除零宽字符、空白和末尾语气标点，不混并不同链接、号码或口令。

候选表 `recruitment_repeats` 仅存同群消息 ID、账号 ID、文案哈希及时间，按配置窗口过期清理。写入和统计在同一个数据库锁内完成，发生在模型调用之前；消息 ID 去重，重复投递不续期，编辑及入群事件不计新消息。首次部署从新消息开始计数，不回填旧日志，也不执行追溯封禁。

## 活动通知的可信来源

抽奖保护只来自已验证群管理员/全局管理员、本群匿名管理员、关联频道的 Telegram 自动转发，或明确配置为白名单的机器人。普通成员自己写“这是抽奖”不能登记口令，普通机器人也不能凭 `is_bot` 获得权限。

- 回复模式：确实回复可信来源的近期通知，通知包含抽奖语义、回复/口令等指示以及当前正文。通知需在 2 小时内，且与当前消息同群。
- 直接发口令模式：可信来源的通知明确写出 `回复“会网购的来”参与抽奖`、`发送"会网购的来"`、`抽奖口令：会网购的来` 或 `回复 会网购的来 参与抽奖` 等格式时，缓存该精确口令哈希 2 小时。期间参与者不必逐条回复通知。通知编辑会替换该通知的旧口令。

缓存只登记会与招揽规则碰撞的明确口令；常见“我要抽奖”“+1”等本来就不会进入招揽计数。抽奖命中使当前消息进入可放行的模型复核，不提供全局免审，也不会让消息附带的其他广告获得永久白名单。未收到活动通知、无法验证来源、不支持的通知格式以及过期活动，不宣称已获验证保护；管理员可使用上述明确的口令格式。

模型输入增加 `recruitment_repeat`、`giveaway_reply`，管理员记录展示重复次数、账号数、窗口及活动匹配状态。此次扩展 MiMo 的行为上下文说明；历史 Jev 实验的 `LEGACY_QUESTIONS` 和已部署的 v2 Questions 保持冻结。
